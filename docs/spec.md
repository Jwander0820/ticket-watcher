# 設計與行為規格

[文件索引](README.md) · [開發指南](development.md) · [資料來源](ticketplus-source.md)

本文件依目前程式整理功能與可靠性約束，更新日期為 2026-10-06。最初依 v0.1 規格及後續對話補充實作；原對話附件未能從工作區取回，本文件不是附件的逐字副本。早期驗證結果另見 [v0.1.0 紀錄](verification.md)，不代表目前功能範圍。

## 功能範圍

Python 核心供 CLI、控制台、VPS 與外部排程共用，使用公開 HTTP API、SQLite 與 Discord Webhook；監控迴圈不需要 AI。套件版本由 `capabilities` 回報。

| 模組 | 目前行為 |
| --- | --- |
| 來源 | TicketPlus `activity` 查 SESSION；`order` 查 AREA 或 PRODUCT |
| 單次操作 | capabilities、query、status、events、check、tick、health、resume |
| 常駐 | CLI `run` 或含監控工作的 `ui` |
| 狀態 | UNKNOWN、UPCOMING、AVAILABLE、SOLD_OUT、TEMPORARILY_UNAVAILABLE、PAUSED、ENDED |
| 通知 | 確認有票 RELEASE、外頁線索 RELEASE_HINT、系統異常／恢復；支援目標各自指定頻道 |
| 持久化 | 基準、排程、停止時間、事件、outbox、平台節流與租約；以 UTC 保存時間 |
| 維運 | 唯讀 health、UI 監控工作恢復、查詢日誌輪替與歷史清理 |
| 部署 | UI／CLI Compose、獨立 named volume、非 root、資源限制與日誌輪替 |

逐席位置、價格篩選、其他售票平台、Discord 指令機器人與 MCP 尚未實作。不加入自動登入、排隊、占位、下單、瀏覽器 fallback 或 IP 輪換。

## 查詢與監控的邊界

`query` 不建立釋票事件、不通知、不覆蓋監控基準或停止時間；仍會保存平台限流、元資料快取及查詢日誌。完整成功的查詢重設平台失敗累計，但不清除伺服器等待期限。查到有票只代表該次來源回報可購票，不能稱剛釋票。

`status`／`events` 不查外部網站。CACHE 保留原觀測時間，本次 UNKNOWN 與最後有效值分開呈現。`status` 摘要由 SQL 統計全部項目，明細只讀指定分頁。

`check` 與 `tick` 比較既有監控基準，符合條件時建立事件並處理通知。`check --now` 和 UI 手動檢測只略過例行排程，仍遵守租約、節流、退避、暫停、停用與停止期限。

來源、URL 或篩選改變時建立新基準，不跨設定簽章判定釋票；單純更換頻道或自動停止開關不重建基準。SESSION 來源由 v1 升為 v2 時亦重新建立基準。

## 票況與釋票判定

| 最後有效狀態 → 本次狀態 | 事件 |
| --- | --- |
| 首次觀測 | 只建立基準 |
| SOLD_OUT → 外頁 TEMPORARILY_UNAVAILABLE | RELEASE_HINT，尚未確認有票 |
| SOLD_OUT／TEMPORARILY_UNAVAILABLE → AVAILABLE | RELEASE |
| 相同狀態持續 | 不重複建立釋票或線索事件 |
| 缺失／無法解析 | UNKNOWN，不猜測為售完 |

內頁 `unavailable` 視為 SOLD_OUT，不套用外頁線索規則。穩定項目以最後有效狀態比較，中間 UNKNOWN 不抹去最後有效值；有效觀測間隔超過 45 分鐘時標示監控空窗。事件時間不是票網精確更新時間。

票區／票種先以完整靜態清單驗證篩選 ID，再查所有選定項目的動態資料。最多 100 個公開場次、1000 個內頁公開項目，動態項目每 100 個分批，輸出分頁不縮減評估範圍。

`remaining_count` 只暴露網站對應的 0～20；超過 20 或不限量顯示「熱賣中」且數量為 null。票種名稱保留身障票等資格區分，不將特殊票種當成一般票餘量。來源欄位與狀態對照見 [TicketPlus 來源說明](ticketplus-source.md)。

## 排程與停止時間

一般輪詢預設隨機 300～900 秒；釋票或線索觸發 60～180 秒快速模式，維持 30 分鐘。再次釋票可延長，持續有票不延長，兩次完整確認無票退出。網路失敗預設 15／30／60 分鐘退避並加入隨機延遲；429 保存共用等待期限，存取拒絕暫停平台，三次解析異常暫停目標。

常駐查票等待最早目標排程、停止期限或平台限制期限，沒有待執行目標時等待變更，不以固定 5 秒掃描。通知依重試、租約、Discord 冷卻與 TTL 期限等待，新通知立即喚醒；未配置 Webhook 的事件只等待過期，不形成重試迴圈。

同程序的手動查詢與解除暫停立即喚醒工作。獨立 30 秒 heartbeat 附帶讀取 SQLite `data_version`，僅在其他連線改變 DB 時喚醒排程；本機 health／status 不重寫相同 schema 版本。跨程序變更最晚於下一次 heartbeat 被發現。

`auto_stop` 預設 true，依公開場次時間與 Asia/Taipei 解析開始時間，期限及選定場次保存於 SQLite 並綁定設定簽章。多場次活動停止已開始場次的通知，所有選定場次都有可靠時間且均已開始，才停止整個目標；未知時間不推算。手動 `stop_at` 與自動期限取較早者，設定與改期處理見 [自動停止指南](configuration.md#演出開始後自動停止)。

已開始場次的缺失票況不再造成其他場次解析失敗；仍在監控的場次資料不完整時保留原保護。單次 query 仍回報來源整體完整性。

## 租約與外部 HTTP

共用 SQLite 的呼叫者使用同一平台租約與至少 5 秒的請求間隔；獨立資料庫不會互相同步。每次查詢使用獨立識別，成功結果、失敗計數及來源快取寫回前都確認有效租約。

租約失效或被接手的結果回傳 `DEFERRED / QUERY_SUPERSEDED`，不覆蓋新票況、不產生釋票事件，也不修改目標失敗計數；實際收到的 429 等待期限與封鎖訊號仍保存平台保護。每個 HTTP 請求發送前再次確認冷卻與暫停，舊限制回應晚到時可在下一個請求前中止查詢。

每個 HTTP 請求同時受整體與讀取逾時限制。回應串流讀取，TicketPlus 傳輸及解壓後資料各限 5,000,000 bytes，Discord ACK 各限 65,536 bytes；支援 gzip／deflate 並限制解壓輸出。429 的 `Retry-After` 不因回應過大或逾時而遺失。

## 通知交易與去重

票況更新、事件與 outbox 入列使用同一 SQLite transaction。通知預設 TTL 10 分鐘，預設首次嘗試加五次重試，使用 `wait=true` 取得 Discord 訊息 ID，停用 mentions。未配置 Webhook 不消耗嘗試次數；過期不補發。

RELEASE 與 RELEASE_HINT 分別處理待送、取消與去重。同輪變更合併通知；票況已不可購買、線索消失或場次開始時，取消或移除待送項目。通知記錄建立時的目的頻道，變更頻道取消舊通知，切回原頻道不恢復。

新通知保存 `target_signature`；每次送信有獨立領取識別，回寫需匹配領取者、嘗試次數與有效租約。取消或被接手的工作不會被晚到回應覆寫，舊版沒有簽章的事件仍相容。

跨系統只能盡量去重：Discord 收到後若成功回應遺失，重試仍可能重複；訊息保留穩定事件 ID。已送出的 HTTP 請求無法撤回。`PENDING` 不等於 `SENT`，成功需有 `message_id`。

## 程序生命週期與控制台

`run` 將查票、送信與 heartbeat 分開執行；`tick` 讓通知與本輪查票並行，等待最後通知批次完成才返回。CLI `check` 會等待一次通知嘗試；UI 手動檢測先回傳票況，通知由背景處理。

UI 替換或重載工作前先取消並等待手動查詢及測試通知，再關閉連線；網路操作不持有設定長鎖，狀態讀取可繼續。新工作建立失敗也由 supervisor 重試，不假造健康狀態。

UI 以 5／15／30／60／300 秒（其後固定 300 秒）重建異常中止的工作，保留 SQLite 狀態及平台保護。同一次故障只建立一則服務中止事件，穩定運作 60 秒後才建立恢復事件；正常關閉／重載不告警。CLI run 錯誤退出後交由程序／容器管理者恢復。詳細操作與告警限制見 [維運指南](operations.md)。

設定回復失敗時，先在背景重試恢復私有設定，完成後才重啟監控與通知，期間拒絕新設定儲存。更換頻道的通知取消會在套用設定時保存，不依賴送信是否冷卻或新工作是否成功啟動。

控制台包含 Host／Origin 白名單、CSRF 與設定版本檢查；預設 loopback，未提供內建登入或多人管理。公開 origin 僅調整白名單，遠端身分驗證由 Access／cloudflared 負責，部署條件見 [VPS 指南](vps-migration.md)。

## 資料與維護

Webhook 存在資料庫旁的私有 JSON，預設頻道優先使用 UI 設定，未設定時才使用環境變數。YAML 只保存頻道 ID／名稱，查詢紀錄不保存網址、憑證、原始回應或例外原文。

歷史事件預設保留 30 天，清理每小時最多一次，未完成工作保留，通知 TTL 獨立檢查。查詢日誌保留目前 7 天週期與上一週期，最長 14 天，週期及輪替進度保存於 SQLite。維護工作等到各自期限，暫時 I/O 失敗才每 30 秒重試；搬移／追加／讀取失敗可接續，不重複輪替提早刪除舊紀錄。

Docker、VPS 與真實 Discord 送達的驗證範圍應獨立記錄；離線測試通過或具備 Compose 設定，不代表已完成遠端部署。
